## 3. First cold boot — PASS

After reset, the stock SPL loaded the carrier and Android enumerated with no
host action. The runner's initial property snapshot was taken slightly early,
so `sys.boot_completed` printed blank at that instant; a follow-up read-only
check showed it settled to `1`.

```text
ro.boot.flash.locked        = 0
ro.boot.verifiedbootstate   = orange
ro.boot.veritymode          = disabled
ro.boot.slot_suffix         = _b
ro.boot.vbmeta.device_state = unlocked
sys.boot_completed          = 1
```

This is the decisive change: the stock SPL accepted the carrier, the magic64
shellcode patched `get_lock_status` at the runtime address `0xB50629B4`, and
LK reported the unlocked/orange state.

## 4. Second and third cold boots — PASS (persistence)

## 5. What this proves

- `[verified: device]` The corrected **post-verification magic64 carrier** is
  accepted by the W202DS stock SPL.
- `[verified: device]` The patch target `0xB50629B4` is correct; the old
  `0x9F0629B4` failure was an address error, not a carrier failure.
- `[verified: device]` The unlock survives three cold boots without the host
  `spl-unlock`.
- `[verified: device]` The current custom system (flag-1 `vbmeta_b` + custom
  `super` + GApps) still boots.

This is the persistent bootloader unlock that was the objective. It is AP-side
unlock, not a secure-world attestation change; that was always the design.
